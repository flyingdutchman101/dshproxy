Without `--resolution`, every route sends the body it sent before. `test/video-resolution.test.js` asserts the exact body for 15 combinations, 14 of them non-default, through the injected `fetch`.

The transport no longer keeps its own list of model ids. It looks the route, model id and resolution up in the catalog, so a resolution can never be sent to a host whose price it does not belong to.

## Commands

- `video quote MODEL [ROUTE] [--resolution R]`
- `video quote MODEL krea --prompt "PROMPT" [--resolution R]`
- `video submit MODEL ROUTE --max-usd AMOUNT --confirm-charge [--resolution R] "PROMPT"` (and `--max-credits`, `--max-units`)
- `video status MODEL ROUTE JOB_ID [--resolution R]`
- `video entries`
- `video entries set MODEL RESOLUTION ROUTE on|off`

`--resolution R` may stand anywhere after the model. A combination that is not an entry is refused before a key is looked for and before any request. The budget check uses the price of the named resolution. The answer carries `resolution` only when one was named.

One addition to an existing answer: `video quote MODEL` (no route) now also prints `workspace`, the clip the model's Krea route runs: `{ route, durationSeconds, aspectRatio, resolution }` or `{ ..., fixedTier }`. The bundle reads it. `video quote MODEL ROUTE` is unchanged.

## Settings

`video-settings.json` keeps `models` as it was. Entries that are on are stored as `"entries": [{ "model", "resolution", "route" }]`, in catalog order. With no entry on, the key is absent, so the file is byte-identical to what an older DSHProxy writes.

- An older file reads as all off.
- A saved entry that is not exactly an entry of today's catalog is ignored on read and gone after the next write, whether that write changes an entry or a model setting.
- Every write runs under the file's lock (`withLock` + `replaceFile`) and is read back before it is reported.
- `settings.entriesOn(home)` returns the entries that are on, each with its `label`.

## Harness bundle

1. **Fixed tier.** `runner.cjs` used the pattern `\d{3,4}p` plus the model name `minimax-h3`. It now reads `workspace` from `video quote MODEL`: a resolution, or a fixed tier. Which one comes from the listing alone. The question still shows `fixed tier (resolution unspecified)`. A listing without `workspace` (an older DSHProxy) is read as before.
2. **Job states.** The command line prints any state of the form `[a-z][a-z0-9_-]{0,63}`; the bundle listed nine. A printable state outside the nine made a sent job report `outcome: unknown` and lose its job id. It now reports `submitted` (or the status answer) with the fixed word `unrecognized` and a note. The provider's own wording is not passed on. The nine listed states are passed on as before. See concern 2.
