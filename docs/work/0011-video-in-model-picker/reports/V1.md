# V1 report

## Result and ruling

Implemented the recorded Krea interface without a real service request or sign-in. The lead ruled that correctness supersedes the old inaccurate MiniMax H3 768p label: the bundle presents a fixed tier with unspecified resolution. For fractional quotes the bundle shows the full quote and asks approval for a cap rounded upward to six decimals; explicit CLI caps are never enlarged. This intentionally corrects two existing bundle answers rather than preserving inaccurate or unusable answers. No edits to `oauth.js` or other out-of-bounds files were made by this worker. Other work appeared concurrently in this shared worktree and is not part of this report.

## Changes

- One model map in `src/video/krea-preset.js`, live unprefixed identifiers, default 720p or fixed tier, and constrained resolution selection. Schema validation checks the fields sent, required fields, value types, bounds and resolution enum while ignoring unused keywords and top-level combinators, as ruled in the ledger. The free preflight remains authoritative.
- `src/krea-helper/mcp.js` negotiates 2025-06-18 or 2025-11-25; uses `generate_video`, `get_job` with `jobId`, and `get_balance`; parses recorded async receipts and fractional preflights; reports unknown job states without submitting; checks the cap and affordability before its sole paid call; maps all failures after sending to `KREA_UNCERTAIN`.
- The IPC accepts balance; workspace CLI accepts balance and optional resolution, preserves existing quote/job JSON shapes, and reports the fixed tier accurately in the manual handoff. Routing code never imports OAuth or holds the token.
- The bundle's runner labels H3 as `fixed tier (resolution unspecified)` rather than using the unrelated API catalog's 768p. The submit approval retains the full quote and presents the upward-rounded cap before approval. The paid call is still single-send; the fresh helper quote is compared against that approved cap.

Zero, excessive, malformed, unaffordable and other unsafe cases remain refused. Other bundle assertions, including confirmation and single-send safety, remain.

## Review follow-up

The independent review requested that a zero-unit quote never authorize a paid submission. `plain preflight and cap are mandatory before paid send` now includes zero units and verifies no paid call, while quote parsing still permits zero. Workspace balance validation now rejects negative monthly units (`workspace balance refuses negative monthly allocation`). `recorded prompt length and duration schema boundaries are enforced` covers recorded H3 and Wan maximum lengths and all four models' recorded duration types and ranges. No real requests were made.

## Evidence limitations and next slice

The evidence describes MiniMax as Frontier 2K but does not identify a precise output resolution; treated as an unspecified fixed tier rather than claiming 2K dimensions. Only a fake server and injected store were used: actual schema changes, authorisation, balance, charging, failed jobs, and real status links require A9 and the user's signed-in session. No paid calls were made. V3 should align its per-route resolution catalog and Flux 3 with this fixed-tier decision, maintain full precision and the explicit approved-cap distinction, and recheck the bundle's conservative unknown-status behavior. The bundle runner currently reads the API catalog's H3 quote before replacing its resolution with the fixed-tier label, so V3 must remove this H3/API-catalog coupling when route-specific entries exist. This was a self-review, not an independent cross-family review.
