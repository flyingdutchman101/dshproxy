# Workspace OAuth release gates

Goal: support an explicit Krea workspace route without reading or writing credentials or implicitly charging a workspace/API balance. Existing API routes and the offline `video krea MODEL` handoff stay functional. A handoff is not a live quote.

1. **Client proof.** Require a structured non-LLM call to an external client bound to exactly `https://api.krea.ai/mcp` using workspace OAuth (no API-key override). Prove behavior with synthetic MCP tools and a temporary isolated profile. Reject unknown model/tool schemas and unavailable clients. Never install software, open a browser, or sign in as part of a quote.
2. **Quote.** Discover the exact standard model and validate provider input names and accepted values against live schemas; insist on a five-second, 16:9 text-only native benchmark. Return only a verified `mode: preflight`, finite nonnegative compute units and quote/affordability flags. Never assume all models exist in the selected workspace. Do not accept ambiguous results as quotes.
3. **Submit/status.** Only enable paid calls when there is evidence the client does not replay tools/call after timeout, session expiry, or ambiguous network errors. Re-preflight the same input immediately prior to submit, require explicit native-unit approval, reject over-budget/unaffordable jobs, and return only validated job data. Poll the existing job, never submit on poll. No alternate payment mechanism, model, host or client fallback.
4. **Release candidate.** Test candidate in isolation together with unrelated pending main changes; independent review, regressions for findings, repeat checks. Leave original checkout unchanged. Do not commit user changes, merge, install or deploy without separate approval.
5. **Live gate.** Before opening an OAuth session or using any real account seek separate approval. Before a paid test obtain exact scope/cap approval and a fresh quote. Mock evidence is not proof of workspace access, model output, latency or debit.

## Client proof outcome (2026-11-22, no real session)

- Installed Codex 0.153.4 exposes a direct `mcpServer/tool/call` RPC and reports the authentication mode, but the installed status schema does not report the effective endpoint. Its binary contains transparent session-reinitialization messages; this investigation did not establish that a paid request cannot be replayed. No real profile was opened.
- [mcporter 0.17.1](https://github.com/openclaw/mcporter/releases/tag/v0.17.1) supports a fixed isolated configuration and cached-only OAuth. Its CLI's `invokeWithAutoCorrection` can dispatch a different tool on an unknown-tool error. A second call cannot be prevented by DSHProxy merely calling that CLI once. It was not installed.
- Both third-party adapters remain disabled. The user selected a dedicated single-send helper, not native token storage in DSHProxy. The CLI talks to a fixed child entry point using private stdio; no session token or provider keys are passed to the router. A separate explicit invocation of the helper performs login. This selection does not authorize an actual login or a paid clip.
- Public, unauthenticated [resource metadata](https://api.krea.ai/.well-known/oauth-protected-resource/mcp) confirms the exact MCP resource and the issuer `https://www.krea.ai`; [issuer metadata](https://www.krea.ai/.well-known/oauth-authorization-server) publishes S256, public-client auth and dynamic registration. Reading metadata is not proof of a successful consent flow or a generation quote. Without a verified schema the exact preset is refused rather than inferred.

Decision rule: if an external client cannot meet a gate, state which capability is proven and which is blocked. Do not quietly replace the integration with generated instructions or native token storage.
