## What was built

1. **`HarnessSetup`** (after `VideoKeys`). Parses the one line of `dsh bundle status --json` and of `dsh bundle install --json`. It never throws: an empty answer, a non-zero exit, a line that is not a JSON object, a missing or wrongly typed field and an unknown `bundle` value are all the state `Unreadable`. The last non-empty line of the output is the one read. It holds every sentence the app says about the video tools (row, page line, checklist, result), so the three places use the same words.
   - States: `Installed`, `SwitchedOff`, `OtherFolder`, `FolderMissing`, `NotInstalled`, `NeverOpened`, `NotFound`, `Unreadable`.
   - Plan for an Apply: `Nothing` (installed or switched off), `Install` (`canInstall` true), `InstallAfterQuit` (not installable only while `harnessRunning`), `Cannot`, `Unknown`.
   - `HarnessSetup.Running` is the static `Func<bool>` for "is a DeepSeek Harness process left". Its real default is `Process.GetProcessesByName("DeepSeek Harness")`, read only; a list that cannot be read counts as running.
2. **Apply** (`MainForm.ApplyToHarness` and the steps under "first-time setup").
   - Reads the state in the background, then shows the checklist (`SetupDialog.Confirm`). Cancel, Esc and the close box run nothing more.
   - Apply runs `dsh apply` as before. A failure shows its message in the old error box and stops.
   - When the plan is to install and a DeepSeek Harness process is left: `HarnessWaitDialog`. It asks once a second, off the UI thread, and closes itself when none is left. Its one button, Esc and the close box skip; nothing is installed then.
   - Then `dsh bundle install --json` once, then one result (`SetupDialog.Show`). The page row is read again at that moment.
   - A second press while one is going returns at once (`applying`).
   - The app never closes, ends or starts DeepSeek Harness and writes into no profile.
   - In a preview window (`--preview`, `--preview-limits`) the button shows the checklist with a sample and then "Sample only: this is a preview window. Nothing was read, written or installed." No command runs.
3. **Video > DeepSeek Harness page.** The first row is now "Video tools installed in DeepSeek Harness?" with the state in words and colour, read when the page is entered and after an Apply. The text above the list is corrected; under the list there is a line saying what was read and when, then a short note. The fixed-height `Foot` helper had no other user and is removed.
4. **Seams.** `HarnessSetup.Parse(line)` plus `MainForm.ShowHarnessSetup(state, readAt)` put any contract line on the page. `HarnessSetup.Running` answers whether Harness is running. `MainForm.UseSetupCommands(run)` replaces the three commands of an Apply, so the layout check drives the real flow from the button press to the result with no command, profile, install or process list touched.
