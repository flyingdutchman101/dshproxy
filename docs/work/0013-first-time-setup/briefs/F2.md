## What to build

1. **Reading the state.** A small class (like `VideoKeys`) that parses the contract's status line into fields and never throws on a bad line: an unreadable answer is its own state, "could not be read".
2. **Apply.** On the button:
   - Read the state in the background (`dsh bundle status --json`), then show one confirmation with a short checklist, in plain words. It says, each on its own line with a mark for done, to do, or cannot: DeepSeek Harness found and opened once (or not); the chat routes will be written into every profile, each backed up first; the video tools: already installed / will be installed / will be installed after you close DeepSeek Harness / will be pointed at this DSHProxy folder (naming the other folder) / switched off in DeepSeek Harness and left off / cannot be installed, with the reason from the status line; and that DeepSeek Harness has to be restarted afterwards. Buttons: go on, or cancel. Cancel changes nothing.
   - Go on: run `dsh apply` as today. If that fails, show its message and stop.
   - Then, if the plugin is to be installed and Harness is running: a waiting dialog, "Quit DeepSeek Harness to install the video tools" in plain words (it may stay in the tray: say so), with one button, "Skip the video tools". It checks once a second whether a `DeepSeek Harness` process is left and closes itself when none is. Skipping installs nothing.
   - Then run `dsh bundle install --json` once in the background and show one result: what Apply wrote (its output as today), what happened to the video tools (the message from the result line), and what to do next (start DeepSeek Harness again; or the manual way when the install did not work: in DeepSeek Harness, Plugins > Add plugin, the folder, which a button or the dialog copies to the clipboard).
   - The app never closes, kills or starts DeepSeek Harness, and never writes into a Harness profile itself.
   - A second press while the first is still going does nothing.
3. **The Video > DeepSeek Harness page.** The row "Bundle installed in DeepSeek Harness?" shows the real state in words and colour (the six states of criterion 1, plus "could not be read"), read when the page is entered and after an Apply. The text above and below the list is corrected to what is now true (the app can tell, and Apply installs it). Keep it short.
4. **Seams for the layout check.** The check must be able to: put any contract line in (a sample per state), and say whether Harness is running, without any real process list, real profile or real install being touched. A static `Func<bool>` for "is Harness running" with the real default is fine. In `ReadOnly` and preview modes nothing is run, as for the other buttons.
